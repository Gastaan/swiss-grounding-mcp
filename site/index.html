Swiss Grounding MCP

An MCP server that gives AI assistants authoritative, cited, jurisdiction-correct answers about Switzerland, from federal, cantonal and municipal sources, in German, French, Italian, Romansh and English.

  • No API keys, no accounts. Everything is public Swiss open data or official web pages.
  • 13 read-only tools, one response contract, citations on every result.
  • Honest by design. Asks back only for missing essentials, says clearly when something is not covered or not in Switzerland, never fills gaps from memory.
  • Runs locally over stdio or as a Streamable HTTP service (/mcp, /health).

Quick start

Requires uv, which installs Python 3.13 automatically.

git clone https://github.com/Gastaan/swiss-grounding-mcp && cd swiss-grounding-mcp
uv sync                                                  # installs dependencies (keyword search)
uv sync --extra semantic                                 # optional: hybrid search
uv run swiss-grounding-mcp                               # stdio (for local MCP clients)
uv run swiss-grounding-mcp --transport http --port 8000  # HTTP: http://localhost:8000/mcp
curl localhost:8000/health

The prebuilt data (municipality register, health premiums, search index) ships in the repository. The first start unpacks the index in about a second.

Docker

docker build -t swiss-grounding-mcp .
docker run -p 8000:8000 swiss-grounding-mcp               # http://localhost:8000/mcp

The image (about 1.4 GB, including hybrid search and its model) listens on all interfaces (HOST=0.0.0.0) as an unprivileged user and never downloads anything at runtime. When its port is reachable from outside a trusted network, add -e SGM_AUTH_TOKEN=<secret>.

Without cloning

uvx --from git+https://github.com/Gastaan/swiss-grounding-mcp swiss-grounding-mcp

Connect a client

Use absolute paths, and replace /path/to/swiss-grounding-mcp with your clone. Any client that speaks MCP over stdio or Streamable HTTP works. Tested with Claude Code, OpenCode, the MCP Inspector CLI and the FastMCP client, including the legacy initialize handshake (protocol 2025-06-18) and the stateless 2026-07-28 protocol.

Response contract

Every tool returns the same JSON object, as structuredContent with an outputSchema and as text.

{
  "status": "ok | needs_context | not_covered | not_found | source_error",
  "summary": "One factual sentence, ending with 'Source: <publisher> – <url>'",
  "data": {"...": "tool-specific facts"},
  "citations": [{"title": "", "url": "", "publisher": "",
                 "level": "federal|cantonal|municipal|semi-official|community",
                 "jurisdiction": "CH | CH-VD | CH-VD-5586", "retrieved_at": "",
                 "valid_for": "", "excerpt": "verbatim"}],
  "missing_context": [{"field": "municipality", "question": "…",
                       "options": ["Buchs (ZH)", "Buchs (SG)"]}],
  "guidance": "what the assistant should do next"
}

Statuses

StatusWhat the assistant does
okAnswers in the user's language, states the reference date and writes out the source URL.
needs_contextAsks the user exactly the question in summary, for example which municipality, or which of three called Buchs.
not_coveredSays the question is outside Switzerland or outside the declared scope.
not_foundSays nothing was found. Never answers from memory.
source_errorSays the official source is unavailable and gives the citation link.

Details

  • Invalid arguments are returned with isError: true and a readable message.
  • data.stale_sources appears when a live source was down and an earlier cached copy was used (at most SGM_MAX_STALE_HOURS old). guidance then tells the assistant to give the user that date.
  • search_official_info sets data.local_match: false when a place was given but no cantonal or municipal page matched as well as the federal ones. The summary says so and the municipality's website is cited.
  • The output schema lists the top-level fields only. The fields inside citations and missing_context are described once in the server instructions, which keeps tools/list small.
  • A jurisdiction is CH, CH-<canton> or CH-<canton>-<BFS municipality number>.

Tools

All tools are read-only (readOnlyHint, idempotentHint) and share the response contract. Pick the specific tool first. For procedures, rules, fees and "how do I…" questions use search_official_info, then read_official_page for detail. Parameters of type place take a municipality, postcode, address or canton in any language; language is one of de, fr, it, rm, en.

Not covered, and limitations

  • Anything outside Switzerland, such as the German broadcasting fee in Konstanz. The server says so.
  • Cantons GR, BL and SH block or do not serve text to automated clients, so their cantonal pages are not in the index. ch.ch and federal pages still apply, and read_official_page reports the block. VS and TI are only partially indexed.
  • Municipal web pages are indexed only for the 12 largest cities. For other municipalities the server returns the official website and can read a given page live.
  • Cantonal law texts, individual tax calculations and weather forecasts are not provided.
  • Waste calendars exist only where municipalities publish open data. Elsewhere the server says so and links the municipality.
  • School holidays come from OpenHolidays, which aggregates official lists. The EDK list and the municipality site are cited alongside for verification.
  • Romansh is not covered by the embedding model used for hybrid search.

Search

search_official_info ranks passages of the index with SQLite FTS5/BM25 plus rules: the user's language, the most specific jurisdiction, and how many query words a passage covers.

With the optional semantic extra it becomes hybrid. A local multilingual embedding model (paraphrase-multilingual-MiniLM-L12-v2, ONNX, no API key) ranks the same passages by meaning, and the two rankings are merged with reciprocal-rank fusion, keeping the preference for cantonal and municipal pages when a place is given. The best keyword hit always keeps first place, so exact matches are never pushed out.

uv sync --extra semantic   # /health then shows "search": "hybrid (…)"

Measured quality

Measured with scripts/search_eval.py: 29 hand-labelled questions whose answer is in the index, plus 5 without one.

Question kindKeyword onlyHybrid
Uses the page's own words (7)77
Same language, other words (8)35
Another language than the only official page (14)28
Answered (29)1220
No correct page exists: says so instead of passing off another page (5)44

A result only counts as evidence if it covers at least half of the query's words or is close in meaning (cosine ≥ 0.7). With no such result the tool answers not_found. The threshold was set so that none of the questions without a correct page gets through by similarity alone.

Costs of the semantic extra. About 240 MB for the model (downloaded once into SGM_MODEL_DIR, or at image build time in Docker), about 130 MB of Python packages, 12 MB for data/embeddings.npz, and about 20 ms per search. Without the extra, or with SGM_SEMANTIC=off, none of it is loaded.

HTTP security

The stdio transport has no network exposure. For --transport http:

  • The server listens on 127.0.0.1 unless HOST or --host says otherwise, and logs a warning when it listens on another interface without a token.
  • Origin check (DNS-rebinding protection). Browser requests whose Origin is not in SGM_ALLOWED_ORIGINS get 403. MCP clients send no Origin header and are unaffected. On localhost the Host header is checked as well.
  • Optional bearer token. With SGM_AUTH_TOKEN set, /mcp and /metrics answer 401 without Authorization: Bearer <token>.
  • Rate limit. SGM_RATE_LIMIT requests per minute per client IP (token bucket), 429 with Retry-After beyond that.
  • The Docker image runs as an unprivileged user.
claude mcp add --transport http swiss-http http://host:8000/mcp \
  --header "Authorization: Bearer <token>"

Caching and etiquette

  • robots.txt is checked per host and cached for 24 h. An unreachable robots.txt (5xx) means "disallow". Documented APIs (geo.admin.ch, Fedlex SPARQL, SNB, OpenHolidays, transport.opendata.ch, open-data portals) are called as APIs; website pages always go through the robots check.
  • Requests identify the project in the User-Agent and are paced per host (SGM_MIN_INTERVAL). Identical requests already in flight share one upstream call.
  • Responses are cached on disk with per-source lifetimes: timetables 1 min, weather and votes 10 min, pages and rates 6 h, waste 12 h, register 1 day, law and holidays 7 days.
  • When a source is down, an expired copy up to SGM_MAX_STALE_HOURS old is served and the result says so. Without a usable copy the result is source_error with the official link. No stack traces reach the model.
  • Every tool call has a time limit (SGM_TOOL_TIMEOUT), so a chain of slow upstream calls ends in a clear source_error instead of a client timeout.
  • read_official_page only reads recognised Swiss government domains: admin.ch, ch.ch, the 26 cantons, about 2,090 municipal websites, and bodies with a legal mandate. Redirects are followed one hop at a time and each target is checked again (allowlist, robots.txt, never a private or reserved address).

Monitoring

  • GET /health: version, data build dates, index size, search mode and sources_with_errors. Used by the Docker HEALTHCHECK.
  • GET /metrics: per tool (calls, statuses, average and maximum latency, average response size) and per upstream host (requests, cache hits, errors, stale copies served, last error).
  • .github/workflows/live-sources.yml calls every real source daily and opens or comments on a source-broken issue when one fails.
  • Logs go to stderr: one line per tool call (tool, status, bytes, ms) and per upstream fetch (host and path, never query strings).

.github/workflows/refresh-data.yml rebuilds everything weekly, the embeddings right after the index so they always match, and opens a pull request that includes the search-quality numbers.

Municipal websites come from Wikidata, which anyone can edit, and they decide which domains count as official. So only .ch and .swiss addresses that are not on a free hosting platform are accepted. Reviewed exceptions live in data/website_overrides.json, and every weekly pull request lists each website that changed or was rejected.

      places.py (register, exonyms, postcodes, geocoding) · authorities.py (domain → level/jurisdiction)

  sources/  search (FTS5 index + live pages) · fedlex · premiums · holidays · waste · transport

                                          │

      guards.py (HTTP only): bearer token · rate limit   + FastMCP Host/Origin check

Python 3.13, fastmcp 4 on the official mcp 2.x SDK, httpx, protego, trafilatura, SQLite FTS5.

Adding a source

  • Write sources/<topic>.py with one async function that returns models.ToolResult. Resolve places with places.resolve() and hand non-municipality results to sources.common.place_problem(), so ambiguous, foreign and unknown places behave like everywhere else.
  • Fetch only through http.fetch() or fetch_json() with a TTL that matches how often the source changes. Pass check_robots=False only for documented APIs.
  • Cite every fact: publisher, level, jurisdiction, retrieved_at or valid_for, and a verbatim excerpt where there is one. Use status honestly: not_covered rather than a guess.
  • Register it in server.py with @tool("Title") and a short docstring. Parameter descriptions are sent on every connection, so keep them brief; a test caps the size of the tool list.
  • Add a row to coverage.py and to the coverage table, an offline test in tests/, and a live check in tests/test_live.py.
